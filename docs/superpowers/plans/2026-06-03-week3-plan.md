# Week 3 Implementation Plan — Planning Agent + Multi-turn UI

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Week 1–2 backend into a **demo-able product**: a multi-turn **LangChain agent** at `POST /agent/chat` that calls the existing retriever as tools and remembers context across turns, plus a **Next.js frontend** with a streaming chat panel and a **Mapbox** map that pins recommended cafes.

**Builds on Weeks 1–2:** FastAPI + Postgres/pgvector, `POST /search`, `slot_extractor`, `Retriever` / `RetrievalRequest`, `Embedder`, `Cafe` ORM, 52 cafes with `ambience_text` + embeddings, eval harness.

**Plain-language overview (read this first):**

- Today the app answers **one question at a time** and only through code/Postman.
- Week 3 adds two things: (1) a **conversation** — ask a follow-up like "anything cheaper?" and it stays on topic; (2) a **website** — a real page with a chat box and a map showing pins. This is the week that makes the project something you can screen-record and show people.
- The agent does **not** replace the Week 1 search. It **wraps** it. The agent is a "manager" that decides *when* to call your existing `/search` logic and how to phrase the answer.

## Decisions locked for Week 3

| ID | Decision | Choice | Why |
|----|----------|--------|-----|
| W3.1 | Map provider | **Mapbox GL JS** (free tier) | Spec default; cleanest Next.js fit; publishable token only in browser |
| W3.2 | Agent framework | **LangChain** ReAct agent, `gpt-4o-mini` (env switch to `gpt-4o`) | Spec C4; cheap, tool-calling capable |

| W3.4 | Streaming | **Server-Sent Events (SSE)** from `/agent/chat` | Simple, works with FastAPI `StreamingResponse` + Next.js `EventSource` |
| W3.5 | Frontend stack | **Next.js (App Router) + TypeScript + pnpm** | Spec C2/C3; reserves Week 5 deploy on Vercel |
| W3.6 | Distance anchor | USC main campus `(34.0224, -118.2851)` as the default map center / "near me" reference | Avoids needing browser geolocation in v1; spec deferred `distance_m` to here |

**Honesty note:** Zep and Mapbox both need free-tier signups (see Task 0). If Zep setup stalls, the agent must still work with **in-process per-session memory** as a fallback (documented), so the frontend demo is never blocked on a third party.

## Task 1: Agent Tools — Thin Wrappers Over Week 1 Code

**Files:**
- Create: `backend/app/agent/tools.py`
- Optional: `backend/tests/unit/test_agent_tools.py`

The agent does not re-implement search. It calls your existing pieces. Build three tools (spec §6 Week 3), each an `async` function plus a LangChain `StructuredTool` wrapper:

1. **`search_shops(query, has_outlet?, price_max?, top_k=5)`** → runs `extract_slots` + `Embedder` + `Retriever` (exactly what `app/api/search.py` does) and returns a compact list of `{id, name, similarity, price_level, has_outlet, noise_level, ambience_text, lat, lng}`.
2. **`filter_by_hours(cafe_ids, day_of_week, time)`** → re-checks `app/search/opening_hours.py` against the given day/time and returns the subset still open.
3. **`get_shop_detail(cafe_id)`** → loads the full `Cafe` row.

- [ ] **Step 1:** Implement the three functions, reusing `app/api/search.py` logic (consider extracting the search body into `app/search/service.py` so both the REST endpoint and the tool call one function — avoids drift).
- [ ] **Step 2:** Wrap each as a LangChain tool with a clear description + Pydantic args schema (the description is what the LLM reads to decide when to call it).
- [ ] **Step 3:** Unit test each tool with a seeded test DB (reuse Week 1/2 `testcontainers` conftest).

## Appendix B: Risk register

| Risk | Mitigation |
|------|------------|
| LangChain version churn | Pin in `uv.lock`; keep the agent logic thin so upgrades are cheap |
| Zep setup eats time | Ship `InProcessMemory` first; Zep is a swap-in behind the `Memory` protocol |
| SSE + CORS friction in the browser | Verify backend SSE with `curl -N` before wiring the frontend |
| Mapbox token leak | Only the **public** `pk.` token reaches the browser; restrict by domain in Mapbox dashboard |
| Frontend is new territory | Build backend Tasks 1–4 fully first (Postman-verifiable) so the frontend only consumes a known-good API |
